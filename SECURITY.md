# Security Policy

## Reporting a Vulnerability

Security is a core consideration across my cybersecurity research and software projects.

If you discover a security vulnerability in a project, please report it responsibly and provide enough information to reproduce and validate the issue.

Please include:

- Clear description of the vulnerability
- Affected component, module, or functionality
- Steps to reproduce
- Security impact and potential risk
- Relevant request/response details, logs, or screenshots where applicable
- Suggested remediation, if available

Please avoid publicly disclosing a vulnerability before it has been reviewed and addressed.

Do not include passwords, API keys, access tokens, personal information, or other sensitive data in vulnerability reports.

## Security Research Scope

Projects in this repository may involve security research, controlled testing, vulnerability analysis, and security automation.

Relevant areas may include:

- API Security
- Authentication & Authorization
- Broken Access Control
- Vulnerability Assessment
- Penetration Testing Methodologies
- Security Research
- Burp Suite Extension Development
- Security Automation
- Detection Engineering
- Digital Forensics
- Secure Software Development

Security testing should only be performed against systems, applications, APIs, and environments for which you have explicit authorization.

## Responsible Disclosure

For vulnerabilities discovered in third-party systems, follow the affected organization's published security policy or responsible disclosure process.

Research conducted through these projects should remain within authorized and controlled environments.
