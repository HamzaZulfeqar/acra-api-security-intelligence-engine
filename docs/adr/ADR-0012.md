# ADR-0012: JWT / Session / OAuth / OIDC Scope

**Status:** ACCEPTED  
**Decision:** Core may model provenance-aware JWT/session and passive OAuth/OIDC security context; active provider
interaction remains separately gated and is not implied by passive observations.  
**Accepted in:** Sprint 11 Phase 1

## Context

Early ACRA sprints intentionally left the JWT/session/OAuth/OIDC boundary open. Sprint 10 subsequently established
the generic authentication/session/token-context layer, including explicit verified-vs-inferred identity state and
secret-safe token correlation.

Sprint 11 now requires a stable boundary for OAuth/OIDC-specific context without converting ACRA into an
unrestricted identity-provider testing client.

## Decision

ACRA may:

- represent JWT/session authentication context using existing identity/session contracts;
- represent OAuth/OIDC issuer, client, resource/audience, scope, flow, PKCE and state/nonce presence as passive
  evidence-backed protocol facts;
- use deterministic secret-safe fingerprints for correlation;
- correlate context changes without automatically declaring a vulnerability;
- expose future parser/analyzer adapters through the existing plugin contracts.

ACRA must not infer from passive metadata alone that:

- a JWT signature is valid;
- an issuer or authorization server is trusted;
- a principal is verified;
- a redirect URI is authorized;
- a token audience/resource is semantically correct;
- missing PKCE/state/nonce proves exploitation.

Active OAuth/OIDC behavior such as authorization-code replay, grant manipulation, token replay, redirect mutation,
provider discovery/probing or external identity-provider testing requires separate scope, safety, consent and
verification decisions.

## Consequences

- Sprint 10 remains the lower-level session/token-context foundation.
- Sprint 11 Phase 1 is passive and network-free.
- Raw access/refresh tokens, authorization codes, state values and nonce values remain outside normal persisted
  domain state.
- Raw redirect URIs are not retained by the Phase 1 OAuth context object; a SHA-256 handle is used for correlation.
- Core domain contracts may represent protocol-neutral facts while traffic parsing/provider-specific behavior can
  remain behind existing plugin/adaptor boundaries.
- Future active OAuth/OIDC testing must preserve ACRA's existing scope, environment, consent, budget, rate,
  concurrency and kill-switch protections.
