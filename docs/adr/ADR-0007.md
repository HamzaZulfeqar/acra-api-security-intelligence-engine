# ADR-0007: Build and Dependency Toolchain

**Status:** ACCEPTED  
**Decision:** Apache Maven `3.9.16` is the repository build/dependency-management baseline; Java 21 remains the compilation runtime.

## Context

Sprint 1 deliberately used dependency-free `javac` verification because no external dependency manager was required. Sprint 2 introduces the PortSwigger Montoya dependency and therefore requires a standard dependency-resolution and packaging tool.

At Sprint 2 review, Apache Maven `3.9.16` is the current recommended Maven 3 GA release.

## Decision

- Use Maven `3.9.16` as the reproducible project build/dependency baseline.
- Use a root reactor POM with `core` and `extension/burp-extension` modules.
- Use Java release 21 with warnings treated as errors for project source.
- Mark Montoya API as `provided` so Burp supplies it at runtime.
- Build a shaded extension artifact containing ACRA dependencies but not the Montoya API.
- Retain JDK-only verification scripts as an offline fallback and as a way to verify core invariants when Maven is unavailable.

## Verification state

The current execution environment has Java 21 but no Maven executable and no dependency-download network path. POM structure is XML-validated and local source is compiled/tested with `javac`, but `mvn package` is **UNVERIFIED** in this environment.

This does not reverse the architecture decision. It means the Maven packaging gate remains pending before v0.2.0 promotion.
